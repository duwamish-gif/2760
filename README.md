# GB 2760-2024 图谱合规系统设计方案

> 设计理念：**数据是复杂的（图谱），但体验是简单的（智能）**。

## 1. 系统总体架构 (System Architecture)

### 1.1 前端 (Frontend)
- **技术栈**：React / Vue3 + Ant Design Pro
- **可视化**：ECharts / D3.js（图谱渲染）
- **布局**：企业级后台布局，强调“左树右表 + 顶部搜索 + 侧边详情”

### 1.2 后端 (Backend)
- **框架**：Spring Boot
- **图谱操作**：Spring Data Neo4j
- **核心引擎**：规则推理引擎（继承、阻断、配方计算）

## 3. 核心功能模块 (Core Modules)

### 3.1 智能合规计算器 (Compliance Checker)
**痛点**：配方合规判断复杂，尤其是混合使用和 GMP 例外规则。

**输入**
- 选择食品分类（例：01.02.02 风味发酵乳）
- 添加成分列表（例：山梨酸钾 0.3 g/kg，苯甲酸钠 0.2 g/kg）

**逻辑处理（后端）**
1. **单项判定**：查询 Neo4j 判断是否允许 & 是否超量
2. **GMP 阻断检查**：
   - 若分类为 GMP 例外，且规则为 GMP 且来自父类 → 直接判定不合规
3. **混合使用计算**：
   - 同一功能（如防腐剂）混合使用时：
     - \(\sum \frac{实际用量}{最大用量} \le 1\)

**输出报告**
- ✅ 通过 / ❌ 不通过
- 详细理由（如 “继承自 01.0”、“混合校验超标”）

### 3.2 反向溯源查询 (Reverse Traceability)
**场景**：研发人员想确定某类食品可用添加剂。

**流程**
- 选择分类：14.0 饮料类
- 筛选功能：防腐剂
- 系统列出该节点及父节点允许的所有防腐剂
- 支持高级筛选（例如排除有“异味”备注的添加剂）

### 3.3 知识图谱可视化 (Knowledge Graph View)
- **全屏模式**：展示 GB 2760 宏观结构
- **节点颜色**
  - 🔵 食品分类
  - 🟢 添加剂
  - 🔴 规则/备注
- **交互**：点击“二氧化硫”高亮所有允许使用的食品类别

## 4. 逻辑流与数据交互设计 (Logic & Data Flow)

### 场景：查询“01.02.02 风味发酵乳”允许添加剂

#### 前端请求
```
GET /api/additives?category=01.02.02
```

#### 后端处理
1. **获取分类属性**
   ```cypher
   MATCH (c:FoodCategory {code: '01.02.02'})
   RETURN c.isGmpException
   ```
2. **递归查找规则**
   ```cypher
   MATCH (c:FoodCategory {code: '01.02.02'})<-[:PARENT_OF*0..]-(ancestor)
   MATCH (ancestor)<-[:APPLIES_TO]-(rule)<-[:REGULATED_BY]-(additive)
   RETURN additive, rule, ancestor
   ```
3. **Java 业务过滤（关键逻辑）**
   - 若 `rule.maxUsage == "按生产需要适量"` 且 `c.isGmpException == true`
   - 且规则来自父类 → **过滤该条目**
4. **单位换算（可选）**
   - 若备注含“以…酸计”，自动提示折算系数

#### 前端渲染
- 返回清洗后的 JSON
- 表格展示并标注“来源”列
